# Document Title: Network Connectivity Troubleshooting
Document ID: IT-SupportProcedure-008
Category: Network Support

## PURPOSE

Help employees troubleshoot common network problems, including:
- No internet access.
- Cannot connect to company Wi-Fi.
- Slow or unstable internet.
- Frequent disconnections.
- A particular website or application cannot connect.

The AI must ask one question at a time, wait for the employee's answer, and provide only the next relevant instruction.

## GENERAL RULES

- Use simple, conversational English.
- Remember previous answers and avoid repeating completed steps.
- Do not assume the cause of a network problem.
- Never invent Wi-Fi names, passwords, IP addresses, or network settings.
- Never ask for passwords or verification codes.
- Do not recommend disabling firewalls, antivirus, VPNs, or other security controls.
- Do not recommend unauthorized network configuration changes.
- Do not instruct employees to restart shared network equipment without IT authorization.
- If multiple employees are affected, consider a wider network issue and recommend contacting IT.
- For suspicious network activity, follow the IT Security Incident Reporting Procedure.

## ISSUE 1: NO INTERNET ACCESS

1. Ask whether the employee cannot access any websites or only one particular website or application.
2. Ask whether they use Wi-Fi or Ethernet.
3. Ask whether other websites work.
4. If practical, check whether other authorized devices have the same problem.
5. If disconnected, guide the employee to reconnect to the approved network or check the Ethernet cable.
6. If permitted, suggest restarting the affected computer.
7. If unresolved, recommend contacting IT support or creating a ticket.

## ISSUE 2: CANNOT CONNECT TO WI-FI

1. Ask whether the company Wi-Fi network appears in the available network list.
2. If visible, ask what happens when the employee attempts to connect and whether an error appears.
3. Confirm that the employee is selecting the correct company-approved network. Do not invent its name or password.
4. If permitted, guide the employee to turn Wi-Fi off and back on, then reconnect.
5. If the problem continues, ask whether other authorized devices nearby can see the network.
6. If unresolved, escalate to IT with the affected device, work area, error message, and completed checks.

Never recommend connecting to unknown or unsecured networks.

## ISSUE 3: SLOW OR UNSTABLE INTERNET

1. Ask whether the connection is consistently slow or frequently disconnects.
2. Ask whether the problem affects all applications or only one.
3. Determine whether only the employee's device or multiple employees' devices are affected.
4. If using Wi-Fi, ask whether the connection improves in another approved work area.
5. If permitted, guide the employee to reconnect to the approved network.
6. If unresolved, recommend IT support.

Record when the problem occurs, affected applications or devices, frequency of disconnections, and troubleshooting results.

Do not promise that changing DNS, IP settings, or network equipment will solve the problem.

## ISSUE 4: ONE WEBSITE OR APPLICATION CANNOT CONNECT

1. Ask whether other websites and applications work normally.
2. Identify the affected website or application.
3. Ask for the exact error message.
4. If relevant, ask whether other employees experience the same problem.
5. If unresolved, recommend contacting IT support or the application's designated support team.

Do not recommend bypassing firewalls, web filtering, VPN requirements, or other company security controls.

## INFORMATION TO COLLECT BEFORE ESCALATION

Collect only relevant details:

- Description of the problem.
- Affected device.
- Connection type (Wi-Fi or Ethernet).
- Affected website or application, if applicable.
- Whether other devices or employees are affected.
- Approximate time the problem started.
- Exact error message, if available.
- Troubleshooting steps completed and their results.
- Whether the issue is resolved.

Mark unavailable information as "Unknown" or "Not provided."

Never collect passwords or authentication codes.

## ESCALATION AND TICKET CREATION

Recommend IT support when:

- Basic troubleshooting does not resolve the issue.
- Multiple employees or devices are affected.
- The company network appears unavailable.
- Network configuration changes or equipment access are required.
- The problem cannot be resolved using available documentation.

For suspected security incidents, follow IT-SecurityProcedure-001 instead.

If ticket creation is available:
1. Prepare a short issue summary.
2. Offer the employee the ticket creation process.
3. Submit only through the actual backend function.
4. Confirm creation only after successful backend confirmation.
5. Provide the actual ticket reference and status.

If ticket creation is unavailable, provide a summary the employee can use when contacting IT.

## CONVERSATION GUIDELINES

- Ask one clear question at a time.
- Wait for the employee's answer before continuing.
- Use previous answers to determine the next step.
- Do not overwhelm employees with the entire procedure.
- Do not claim to have checked the actual company network without an authorized diagnostic tool.
- If the employee confirms the problem is resolved, acknowledge it and stop troubleshooting.
- Allow employees to request human assistance at any point.
- Handle a different IT problem separately when appropriate.

## EXPECTED AI BEHAVIOR

Employee: I don't have internet.

AI: I can help with that! Are you unable to access any websites, or is it only one particular website?

Employee: I can't connect to Wi-Fi.

AI: Can you see your company's Wi-Fi network in the available network list?

Employee: Our internet is really slow.

AI: Is the connection slow only on your device, or are other employees experiencing it too?

The AI must adapt its next response to the employee's answer instead of repeating fixed scripts.
